AxetosOS Products / NES v1.1.4

Purpose
-------
Correct the final three failures reported after v1.1.3 while preserving the strict pin-reactive chip boundary.

Changes
-------
- DigitalPin: an actively driven bidirectional pin no longer updates its retained input sample from its own resolved net output.
- Mos6502BusAnalyzer: read-cycle data remains open during PHI2-high so a controller, ROM, RAM, or other responder can provide the settled value after the rising edge.
- NesPpuRegisterPackage: the RP2C02 now owns and arbitrates its external PPU bus internally between CPU PPUDATA access and rendering. CPU-side PPU reads/writes cannot be mistaken for renderer fetch responses.
- The renderer keeps an interrupted fetch state and re-issues it through the same PPU pins when CPU PPUDATA releases the bus.
- Corrected the older boundary regression test: driving and releasing a bidirectional pin cannot invent an input transition when the external level never changed.

Architecture
------------
- Chips still execute only because input-capable pins receive changed electrical levels.
- Chips still affect the machine only by driving/releasing their own output-capable pins.
- No Evaluate polling, lifecycle callback, peer-chip reference, direct memory call, or scheduler-owned chip work was restored.

Validation
----------
Static source, forbidden-pattern, archive-integrity, and patch-overlay validation performed in the packaging environment. dotnet is unavailable in that environment, so the target machine must run dotnet test.
