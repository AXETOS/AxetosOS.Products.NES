AxetosOS Products / NES v1.3.4

Goal
----
Remove the remaining per-master-cycle software loop from normal Release execution while preserving the queue-free physical clock-pin model.

Runtime changes
---------------
- Add harmonic skipping to the topology-validated master-clock execution plan.
- When the oscillator is Low and every receiver on the compiled clock trace is a rising-edge input, cycles that cannot reach any receiver activation boundary are advanced arithmetically.
- The oscillator HalfCycleCount remains exact.
- Each clock pin MasterClockRisingEdgeCount and chip-owned divider phase remain exact.
- The next activating Low -> High edge is still physically presented through the clock net and wakes the appropriate package(s) synchronously.
- The matching High -> Low edge is still presented for each activating cycle.
- Single-half-cycle stepping and profiling retain the scalar clock path.
- No signal queue, component queue, motherboard scheduler, polling, or Settle processing is introduced.

Expected hot-path effect
------------------------
- Famicom/NTSC RP2C02 activates every fourth master-clock rise.
- RP2A03 activates every sixth master-clock rise.
- Their combined activation boundaries repeat over twelve master cycles, so normal batched execution can skip the cycles on which neither chip can react instead of dispatching every master cycle in software.

Validation
----------
- Added a regression test comparing batched master-cycle execution against scalar half-cycle execution for clock counts, CPU progress, M2 state, and PPU raster state.
- Static source/overlay checks performed in packaging environment.
- .NET SDK unavailable here; dotnet test and FPS are not claimed.
