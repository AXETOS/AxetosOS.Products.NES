AxetosOS Products / NES v1.3.0

Purpose
-------
Replace the remaining central propagation queues/settlement runtime with the
simple physical motherboard model: changed output pin -> trace -> resolved 0/1
-> changed input pin -> receiving chip reaction.

Changes
-------
- DigitalPin.Drive() propagates its physical consequence immediately.
- DigitalNet directly resolves connected drivers and presents the resulting
  level to connected input pins; no net queue or scheduler index remains.
- Removed the component activation queue and changed-input-mask queueing.
- All receivers on one trace see the new pin level before package reactions
  begin; package reactions then execute directly without a scheduler.
- Same-net re-entrant changes supersede an older in-flight level by generation,
  not by queueing another event.
- CompiledClockExecutionPlan now only toggles the oscillator output. The clock
  trace performs normal immediate propagation like any other physical trace.
- Removed runtime Simulator.Settle() calls from motherboard power/reset/clock/
  controller paths and the pin-driven sample board.
- VirtualHardwareSimulator is now topology compilation plus opt-in diagnostics.
  Settle() remains only as a no-op compatibility point for older callers/tests.
- Added regressions proving propagation completes without Settle() and that the
  simulator has no runtime queue fields.
- Existing chip isolation remains: chips know only their own pins/internal state
  and can affect the board only through their own outputs.

Validation
----------
This environment has no .NET SDK. Static source/reference checks and patch
overlay verification were performed. Run dotnet test on the target Windows
machine before treating v1.3.0 as validated.
