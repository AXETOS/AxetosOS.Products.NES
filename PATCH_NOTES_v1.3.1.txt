AxetosOS Products / NES v1.3.1

Purpose
-------
Fix the v1.3.0 ordering regression without restoring any central propagation
queue. Keep immediate motherboard trace delivery while making one chip reaction
atomic at the package boundary.

Changes
-------
- A chip reaction may update several of its own output pins. Those drive states
  are now published as one direct package output change-set.
- All traces affected by that package reaction resolve/present their final
  levels before any receiving package executes.
- Receiving packages coalesce only the changed input-pin mask for that direct
  change-set, then react immediately. There is no motherboard/simulator queue.
- Re-entrant inputs arriving while a chip is already running stay local to that
  chip and are handled before its current call chain returns.
- Simulator topology startup now presents every static trace first and only then
  allows packages to react, preventing construction-order reset/power glitches.
- Corrected three tests whose signal sequences depended on the removed Settle()
  batching behavior. Their sources now change in physically safe order.
- Added regressions proving one package's multi-pin output change reaches a
  receiver as one complete state and that first activation sees complete initial
  board levels.

Observed v1.3.0 failure pattern addressed
----------------------------------------
- RP2C02 bus read completion duplicated (expected 1, observed 2).
- OAM DMA writes doubled (expected 256, observed 512).
- PPU/CPU/controller buses could be sampled while only part of a package's
  outputs had propagated.
- Startup could react to VCC/GND/reset one trace at a time.

Validation
----------
This environment has no .NET SDK. Static source/reference checks and patch
overlay verification are performed here. Run dotnet test on the target Windows
machine before treating v1.3.1 as validated.
